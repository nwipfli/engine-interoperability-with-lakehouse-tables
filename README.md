# Multi-Engine Lakehouse Interoperability with Apache Iceberg on Google Cloud

This repository provides an end-to-end demonstration of multi-engine Lakehouse table interoperability on Google Cloud. It showcases how **Google BigQuery** and **Managed Apache Spark Serverless** seamlessly share, mutate, evolve schemas, and query **Apache Iceberg tables** managed by the **Lakehouse Iceberg REST Catalog** without data duplication, proprietary formats, or catalog lock-in.

---

## Overview

Modern data lakehouses require flexible compute options where different analytical and data engineering workloads can operate on the same data footprint simultaneously.

This project demonstrates:
* **Unified Metadata & Open Storage**: Apache Iceberg tables backed by Google Cloud Storage (GCS) in Parquet format, orchestrated via the **Lakehouse Iceberg REST Catalog** as the centralized source of truth.
* **Google BigQuery Capabilities**: Performing standard SQL queries, ACID DML (`INSERT`, `UPDATE`), in-place schema evolution (`ALTER TABLE`), and Generative AI text generation via BigQuery ML and the **Gemini Enterprise Agent Platform**.
* **Managed Apache Spark Serverless**: Connecting to the Lakehouse REST Catalog via Spark Connect and vended credentials, performing distributed reads, writing new records, creating partitioned Iceberg v2 tables, and sharing datasets bidirectionally with BigQuery.
* **Zero-Copy Cross-Engine Visibility**: Immediate consistency when switching between BigQuery and Spark without data migration, sync jobs, or manual schema alignment.

---

## Key Concepts Demonstrated

### 1. Centralized Lakehouse Iceberg REST Catalog
The Lakehouse Iceberg REST Catalog implements the open Apache Iceberg REST Catalog specification, providing standard API endpoints for table discovery, commit orchestration, and snapshot management.

### 2. Vended Credentials Authentication
Managed Apache Spark Serverless authenticates to the Lakehouse REST Catalog using `GoogleAuthManager` with `vended-credentials`. The catalog dispenses short-lived, scoped credentials for underlying Cloud Storage buckets directly to the Spark engine, avoiding static credential management.

### 3. In-Place Schema Evolution & In-Database AI Enrichment
* **Schema Evolution**: Adding columns (`tip_category`, `trip_ai_summary`) in BigQuery updates metadata instantly without rewriting existing Parquet data files.
* **Generative AI via Gemini Enterprise Agent Platform**: Using BigQuery ML's `ML.GENERATE_TEXT` with `gemini-3.6-flash` to evaluate trip features and generate passenger profile tags directly within SQL, committing the results back to the Iceberg table.

### 4. Bidirectional DML & Partition Interoperability
* Tables created in Managed Apache Spark Serverless configured with `'gcp.biglake.bigquery-dml.enabled' = 'true'` allow BigQuery to perform full ACID DML operations (`INSERT`, `UPDATE`, `DELETE`, `MERGE`).
* BigQuery honors Iceberg partition specifications created in Spark (such as `days(pickup_time)`), enabling partition pruning across records generated by both engines.

## Quickstart Guide

### Step 1: Configure Environment Variables
Copy the example environment template and fill in your Google Cloud configuration:

```bash
cp .env.example .env
```

Edit `.env` with your project parameters:
```bash
# Google Cloud Project & Region
PROJECT_ID="your-project-id"
REGION="us-central1"

# Lakehouse Iceberg Catalog & Storage
CATALOG_NAME="engine_interoperability_demo"
WAREHOUSE_BUCKET="your-unique-bucket-name"

# User Identity for Administrative Roles
USER_EMAIL="your-email@example.com"
```

### Step 2: Provision Cloud Infrastructure
Make the setup script executable and run it:

```bash
chmod +x setup.sh clean_up.sh
./setup.sh
```

The script will:
* Enable `biglake.googleapis.com`, `bigquery.googleapis.com`, `dataproc.googleapis.com`, `aiplatform.googleapis.com`, and related services.
* Assign administrative IAM roles to the specified user.
* Create a BigQuery Cloud Resource Connection (`vertex_ai_conn`) for the Gemini Enterprise Agent Platform.
* Provision the GCS Lakehouse warehouse bucket.
* Create the Lakehouse Iceberg REST Catalog with `vended-credentials` mode.
* Create the `default` namespace and `iceberg_table_test` table from `table_definition.json`.
* Enable BigQuery DML support on table properties (`gcp.biglake.bigquery-dml.enabled=true`).

### Step 3: Run the Interactive Demo Notebook
Open [cross_engine_demo.ipynb](file:///home/nwipfli/personal_assets/temp/engine_interoperability_with_lakehouse_tables/cross_engine_demo.ipynb) in **Google Colab**, **Vertex AI Workbench**, or your local **JupyterLab** environment.

#### Walkthrough Flow in Notebook:
1. **BigQuery Ingestion**: Insert initial NYC Taxi trip records into the Lakehouse table via BigQuery DML.
2. **Schema Evolution**: Alter the table to add `tip_category` and populate it via BigQuery `UPDATE`.
3. **GenAI Enrichment**: Create `gemini_analyzer` model pointing to `gemini-3.6-flash`, add `trip_ai_summary`, and run `ML.GENERATE_TEXT` to generate passenger behavioral profile tags.
4. **Spark Connect Setup**: Initialize Managed Apache Spark Serverless session configured with the Lakehouse REST Catalog and vended credentials.
5. **Cross-Engine Read/Write**: Read the BigQuery-enriched Iceberg table in Spark, append new records via Spark SQL, and immediately query the updated dataset in BigQuery.
6. **Spark Table Creation**: Create a new partitioned Iceberg v2 table (`taxi_trips_spark`) in Spark.
7. **BigQuery DML & Partition Pruning**: Insert data into the Spark-created table from BigQuery and execute partition-pruned analytical queries.
8. **Teardown**: Stop the active Spark session.

### Step 4: Environment Cleanup & Teardown
When finished testing, execute the cleanup script to remove all provisioned GCP resources:

```bash
./clean_up.sh
```

## Technical Details

### Spark Configuration for Lakehouse Iceberg REST Catalog

When initializing Managed Apache Spark Serverless (or any Apache Spark runtime), configure the catalog properties as follows:

```python
session.runtime_config.properties = {
    "spark.sql.extensions": "org.apache.iceberg.spark.extensions.IcebergSparkSessionExtensions",
    f"spark.sql.catalog.{CATALOG_NAME}": "org.apache.iceberg.spark.SparkCatalog",
    f"spark.sql.catalog.{CATALOG_NAME}.type": "rest",
    f"spark.sql.catalog.{CATALOG_NAME}.uri": "https://biglake.googleapis.com/iceberg/v1/restcatalog",
    f"spark.sql.catalog.{CATALOG_NAME}.warehouse": f"bl://projects/{PROJECT_ID}/catalogs/{CATALOG_NAME}",
    f"spark.sql.catalog.{CATALOG_NAME}.io-impl": "org.apache.iceberg.gcp.gcs.GCSFileIO",
    f"spark.sql.catalog.{CATALOG_NAME}.rest.auth.type": "org.apache.iceberg.gcp.auth.GoogleAuthManager",
    f"spark.sql.catalog.{CATALOG_NAME}.header.x-goog-user-project": PROJECT_ID,
    f"spark.sql.catalog.{CATALOG_NAME}.header.X-Iceberg-Access-Delegation": "vended-credentials",
}
```

### Table Properties for Multi-Engine DML

When creating tables from Apache Spark that will be mutated by Google BigQuery, ensure the following table properties are included in the `CREATE TABLE` DDL:

```sql
TBLPROPERTIES (
    'format-version' = '2',
    'gcp.biglake.bigquery-dml.enabled' = 'true'
)
```

## Security & Governance Best Practices

* **Centralized Access Control**: Combine Lakehouse Iceberg tables with Google Cloud Dataplex for centralized governance, data lineage, and fine-grained column/row access policies.
* **Credential Isolation**: Using `vended-credentials` ensures that compute engines only receive short-lived access tokens for specific tables and paths rather than broad GCS bucket permissions.
* **Open Formats**: Storing data in Apache Iceberg on Google Cloud Storage prevents vendor lock-in and allows seamless integration with third-party query engines (Trino, Flink, DuckDB, Presto).
